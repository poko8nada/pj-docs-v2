# work — Goal / Discover

Use when this `/work` session advances **Goal** and/or **Discover** (axes, softs, cheap media). Soft skills are normal here. Opening `[Build]` when Goal + Discover are agreed also belongs here.

Build-stage product implementation + Test policy → `build.md` (softs are still allowed there too).

## Inventory sources

- Open `[Goal]` / `[Discover]` bodies (overview + why + agreed)
- Soft comments (`## soft: …`) and cited `findings/` paths
- Session scope agreed in discussion

List in-scope concerns in chat, then slice. Do not slice from an empty list.

## What this situation often does

- Run softs (`feasibility`, `foundation`, `grain`, `inventory`, `data-model`) → write `findings/` → update the one soft comment via `issue`
- Cheap media only while Discovering (look workshop / spike / disposable HTML) — do not invent Goal by rebuilding the product tree
- Update Goal / Discover axes (and agreed) when the slice’s outcome warrants it
- Create `[Build]` when Goal + Discover are both agreed and the user wants product work

Harness / meta → `/chore`.

## Slice shape (examples — teach growth order; do not force-fit)

- Soft: one look-workshop pass / one research question cluster → findings → soft comment refresh
- Look: lock HTML/CSS in the workshop → then Discover Look agreed (separate slice if discussion needed)
- Stack: feasibility run → findings → Stack axis + soft comment
- Data (Narrow): data-model for discussion / look materials → findings → soft comment
- Goal: one covenant axis (What / Goal / Non-goal) after Discover material exists — not a product rebuild
- Ready for Build: create `[Build]` with Links + thin Roadmap/Test/Deploy — not implementation yet

One sitting, one verifiable concern, chat agreement before execute. Fidelity still applies (realistic look content, honest research — not filler).

## Test policy

Not the focus here. If a slice happens to touch product logic, either keep it out of this situation or switch to `build.md` and apply Test policy there. Default for pure soft / issue / cheap-media slices: Test `N/A`.

## After a slice

Commit when agreed (per slice or batched). Update issues at milestones or when the slice’s deliverable is an axis/soft comment change. If direction stalls, name `/discussion`.
